Use `pyenv` for the best Python version management (just like `nvm` for Node.js). If you prefer simplicity, Homebrew works too, but `pyenv` gives more control.

#### **Using `pyenv`**

1. **Install `pyenv`** (if not already installed):
   ```sh
   brew install pyenv
   ```
2. **Install Python 3.10**:
   ```sh
   pyenv install 3.10
   ```
3. **Set Python 3.10 as the global default**:
   ```sh
   pyenv global 3.10
   ```
4. **Verify the Python version**:
   ```sh
   python3 --version
   ```
   (Should output `Python 3.10.x`)
5. Activate pyenv’s Python 3.10.x for your project:
   ```sh
   pyenv shell 3.10.18    # Sets Python for current shell only
   # Or:
   pyenv local 3.10.18    # Creates `.python-version` file for project
   # Verify with:
   python3 --version       # Should now show "Python 3.10.18"
   ```
6. **Install dependencies**:
   ```sh
   python3 -m venv venv           # Create a virtual environment
   source venv/bin/activate      # Activate (macOS/Linux)
   venv\Scripts\activate         # Activate (Windows)
   pip install --upgrade pip      # Ensure pip is up-to-date
   pip install -r requirements.txt  # Install project dependencies
   ```
7. Uninstall unused Python versions:
   ```sh
   pyenv uninstall 3.9.0  # Example
   ```

#### **Basic `pyenv` Commands (vs `nvm`):**

| **Action**        | **`pyenv` Command**     | **`nvm` Equivalent**  |
| ----------------- | ----------------------- | --------------------- |
| Install a version | `pyenv install 3.10`    | `nvm install 14`      |
| Set global        | `pyenv global 3.10`     | `nvm use --global 14` |
| Set local         | `pyenv local 3.10`      | `nvm use 14`          |
| List versions     | `pyenv versions`        | `nvm ls`              |
| Check current     | `pyenv version`         | `nvm current`         |
| Uninstall version | `pyenv uninstall 3.9.0` | `nvm uninstall 14`    |
| Check version     | `python3 --version`     | `node -v`             |

#### **Why Use `pyenv`?**

- Avoid conflicts with system level Python.
- Manage different Python versions for different projects.
- Works seamlessly with virtual environments (`venv`, `pipenv`, etc.).
